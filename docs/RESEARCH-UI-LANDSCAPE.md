# Closing sas-ui's ERP and Arabic gaps (سد فجوات المكتبة)

**Bottom line:** the market gives sas-ui a clear opening. Nobody ships free ERP-grade blocks, and nobody ships RTL-first Arabic-aware date, number and search handling on a Tailwind v4 / Base UI stack. The official shadcn/ui catalogue is only 27 blocks (sidebar, login, signup and one dashboard) on 66 component docs, with no data grid, stepper, tree, kanban or file upload ([GitHub listing](https://api.github.com/repos/shadcn-ui/ui/contents/apps/v4/registry/new-york-v4/blocks), [components index](https://ui.shadcn.com/docs/components)). The paid suites go further: MUI X has a data grid, pickers and a scheduler, and Ant Design Pro has about 20 admin pages. They are CSS-in-JS or npm-only, and none treats Arabic as a first-class case. sas-ui already covers most of the component surface that matters (DataTable, FilterBar, pickers, Tree, FileUpload, Chart, rich text, shell, command palette), so the next work is composition and Arabic depth, not more primitives. The ranked priorities are: (1) a resource-list block and a record-detail block that wire existing parts into the two screens every ERP is made of; (2) Hijri (Umm al-Qura) support plus month/year dropdowns in Calendar, the one feature MUI only half delivers and antd, Fluent and PrimeReact lack; (3) a DataTable v2 (virtualisation, RTL keyboard mapping, grouping, export, saved views); (4) a status-bar/stage component and an advanced filter builder; (5) distribution: publish to npm, host a registry URL, add `registry:block` items. Much of the evidence is secondary or vendor-stated (see the confidence section), and every effort figure is my own estimate.

## Four distribution models, and only one of them owns blocks

The market sorts into four camps, and the camp determines how blocks are packaged. The first is the **copy-in registry**: shadcn/ui and its ecosystem. Its registry is a generic file protocol with 12 item types (`registry:block`, `registry:page`, `registry:theme`, `registry:font`, `registry:base` and others), namespaced URL templates, GitHub repos as registries, dynamic search, and a CLI that supports `add --dry-run/--diff/--view`, preset short codes and an MCP server ([registry-item docs](https://ui.shadcn.com/docs/registry/registry-item-json), [CLI docs](https://ui.shadcn.com/docs/cli), [namespaces](https://ui.shadcn.com/docs/registry/namespace), [GitHub registries](https://ui.shadcn.com/docs/changelog/2026-06-github-registries)). Base UI has been the default primitive layer since July 2026, with Radix and React Aria still selectable ([changelog](https://ui.shadcn.com/docs/changelog/2026-07-base-ui-default)). The second camp is the **npm suite**: MUI, antd, Fluent, PrimeReact, Mantine, Chakra, HeroUI, Radix Themes. Blocks there are separate sites or paid templates. The third camp is the **headless layer** (Base UI, React Aria Components, Ark UI), which ships no styling and almost no blocks; Park UI is the styled copy-in layer over Ark ([Park UI](https://park-ui.com/)). The fourth camp is **snippet kits** (Tailwind Plus/Catalyst, Preline, Flowbite, HyperUI, Tremor Blocks, daisyUI): copy-paste HTML or React with no state or data contract.

Where blocks live differs sharply. Blocks are a first-class registry type only in shadcn, where every block now ships Radix and Base UI variants and `npx shadcn add login-01` resolves the right one ([Blocks changelog](https://ui.shadcn.com/docs/changelog/2026-02-blocks)). Elsewhere they are a product: Mantine UI has **123 free MIT components** (82 application UI, 30 page sections, 11 blog) ([Mantine UI](https://ui.mantine.dev/)); Tremor Blocks has 300+ and became free under MIT after Vercel acquired it ([Vercel](https://vercel.com/blog/vercel-acquires-tremor)); Preline has 204 free blocks and 5 templates, with Pro adding 740 blocks and 21 templates ([Preline](https://github.com/htmlstreamofficial/preline)); Untitled UI claims 5,000+ components and 250+ page examples with a CLI, React Aria and an MCP server ([Untitled UI](https://www.untitledui.com/react)); Shadcnblocks claims 2,866 blocks ([Shadcnblocks](https://www.shadcnblocks.com/)); ReUI Pro claims 678 blocks, including 305 "Application" blocks, for $249 one-time ([ReUI](https://reui.io/)). Tailwind Plus remains the reference taxonomy (11 application categories, 49 subcategories) but closed to new buyers after Tailwind Labs joined Shopify on 9 September 2026 per secondary coverage ([CMSWire](https://www.cmswire.com/digital-experience/shopify-acquires-tailwind-labs-to-secure-css-framework/)).

The admin-framework tier shows what a real ERP page set looks like. Ant Design Pro ships Dashboard (Analysis, Monitor, Workplace), Form (Basic, Step, Advanced), List (search, table, card), Profile, Result, Exception (403/404/500), Account Center/Settings, and Login/Register ([README](https://raw.githubusercontent.com/ant-design/ant-design-pro/master/README.md)). Odoo defines 14 view types, among them form, list, kanban, calendar, pivot, graph and gantt, with a header/statusbar and notebook tabs in its form view ([Odoo 18](https://www.odoo.com/documentation/18.0/developer/reference/user_interface/view_architectures.html)). react-admin gates audit logs, revisions, a full calendar, tree and scheduler behind its Enterprise edition ([react-admin](https://marmelab.com/react-admin/Features.html)). The free shadcn dashboards (satnaing/shadcn-admin at 16.7k stars; Kiranism's starter at about 7.3k stars, already on Base UI) offer shells, tables, charts, kanban and settings, but no status-bar workflow, approval timeline, import wizard, pivot or print layouts ([shadcn-admin](https://github.com/satnaing/shadcn-admin), [Kiranism](https://github.com/Kiranism/next-shadcn-dashboard-starter)).

## Six hard components: only Mantine, PrimeReact and React Aria come close to complete

The six components that decide whether an ERP library is credible split the field cleanly. **Data tables**: PrimeReact's free DataTable is the broadest benchmark, with frozen columns, row grouping, cell and row editing, lazy and virtual scroll, export and column resize ([v10 DataTable](https://v10.primereact.org/datatable/)). Ant Design's free Table adds fixed columns, tree data, virtual scroll and summary rows but is thin on accessibility documentation ([antd Table](https://ant.design/components/table/)). MUI paywalls the same features: pinning, tree data and virtualisation at Pro, row grouping, aggregation and Excel export at Premium, at $299 and $599 per developer per year ([licensing](https://mui.com/x/introduction/licensing/), [pricing](https://mui.com/pricing/)). shadcn offers only a TanStack guide with sorting, one-column filtering, pagination and selection ([Data Table](https://ui.shadcn.com/docs/components/data-table)). **Date pickers**: Mantine has 20 date components on dayjs; React Aria has the richest calendar engine; MUI has the only mainstream Hijri adapter, and its docs admit it does not support the new field components. **Charts**: Mantine ships 22 types, shadcn 70 Recharts examples across 7 categories, MUI Community only scatter, bar, line and donut, with funnel and heatmap in Pro. **Upload**: antd, Chakra/Ark, Mantine Dropzone and React Aria DropZone exist; MUI, Radix and shadcn core have none. **Rich text**: Mantine (Tiptap) and Chakra (new) only; PrimeReact via its Editor. **Command palette**: shadcn Command, Mantine Spotlight, Chakra Command, Tailwind Plus and Untitled UI have one; MUI, antd and Fluent do not.

## The Arabic baseline is low, and Hijri is the clearest differentiator

Every major suite supports RTL mechanically, but the mechanisms differ in robustness. MUI needs both `createTheme({ direction })` and a Stylis plugin in the Emotion cache, and portals do not inherit `dir` ([MUI RTL](https://mui.com/material-ui/customization/right-to-left/)). Fluent flips physical CSS at runtime. PrimeReact v11 and PrimeVue v4 rely on logical properties so document `dir` is enough ([PrimeVue RTL](https://v4.primevue.org/guides/rtl/)). shadcn converts classes to logical ones at install time, and itself documents that Calendar, Pagination and Sidebar need manual work and that portaled content needs an explicit `dir` ([shadcn RTL](https://ui.shadcn.com/docs/rtl)). Radix closed a request to read `<html dir>` automatically as "not planned" ([#3830](https://github.com/radix-ui/primitives/issues/3830)). Base UI's `DirectionProvider` changes JS behaviour only and "does not affect HTML and CSS" ([docs](https://base-ui.com/react/utils/direction-provider)). react-admin's and refine's docs pages checked mention no RTL.

Calendar systems are where the field is thinnest. React Aria's `@internationalized/date` offers 13 calendars, including `islamic-civil`, `islamic-tbla` and `islamic-umalqura` ([docs](https://react-aria.adobe.com/internationalized/date/Calendar)); MUI X has a moment-hijri adapter with the field-component limitation; Ark exposes `createCalendar`; react-day-picker has a dedicated Hijri package with Arabic-Indic digits ([DayPicker](https://daypicker.dev/localization/hijri)). Ant Design, Fluent and PrimeReact show no Hijri support in what was readable. Arabic-Indic numerals were not documented as a feature by any suite; they fall out of `Intl`. W3C's Arabic layout requirements add rules few libraries encode: Arabic-Indic digits are bidi class AN while European digits are EN, percent signs precede Arabic-Indic numbers, letter-spacing breaks joins, and Iraq appears in the list of Arabic-Indic-digit regions ([alreq](https://www.w3.org/TR/alreq/)). Evidence on what Iraqi business users actually prefer is weak: ERP forum threads show users wanting Latin digits in Arabic accounting UIs, but nothing is Iraq-specific ([Odoo forum](https://www.odoo.com/forum/help-1/change-numeralsnumbers-in-arabic-language-196342)). The right design is therefore a per-tenant setting, not a locale inference.

## What sas-ui already has, and the gaps that remain

Inspecting the repository confirms a strong base: 87 registry items, 1,565 tests including axe and Arabic/RTL cases, the CLI with `init/add/diff/list/theme`, four presets with an AA contrast gate, and a `login-01` block in progress (repo `docs/STATUS.md`, `packages/registry`). Three Arabic features exist in code already: Intl locale tags with a `-u-nu-latn` / `-u-nu-arab` switch in `date-utils.ts`, an Arabic search normaliser (alef variants, ya/alef-maksura, tashkeel and tatweel) in `command-filter.ts` and `tree-utils.ts`, and a font stack of IBM Plex Sans / Plex Sans Arabic / Cairo in the tokens. That matches the techniques the notes recommend.

The gaps fall into five groups. **Components**: no Hijri or Umm al-Qura calendar (grep finds nothing); Calendar lacks month/year dropdowns, which shadcn's `captionLayout="dropdown"` has; the calendar is `Date`-based, so Hijri needs either `@internationalized/date` or an Intl-driven month grid, which is a design decision rather than a flag. DataTable has sticky columns and toolbar pieces but the notes put virtualisation with `aria-rowcount`, grouping, inline editing and export on the benchmark list ([APG grid](https://www.w3.org/WAI/ARIA/apg/patterns/grid/)). Missing outright: status-bar/stage component, advanced filter or query builder, phone/currency/mask/tags/OTP inputs, kanban, notification centre, sparkline/bar-list/tracker, and wrappers for the Base UI parts with no sas-ui equivalent (Autocomplete, Collapsible, Toggle and ToggleGroup, Toolbar, Menubar, NavigationMenu, Meter, PreviewCard, OTP Field, CheckboxGroup). Scheduler, Gantt, org chart and tour are further out. **Blocks**: only `login-01` exists, against 27 in shadcn and an ERP page set in Ant Design Pro. **Distribution**: nothing is published, there is no hosted docs site or registry URL, and `add` reads a registry bundled in the CLI. The shadcn model suggests namespaced URL templates, `registry:block`/`page`/`theme`/`font` item types, `include`, search and an MCP server. **Theming**: four presets and no density mode, whereas antd ships a compact algorithm and Radix Themes a `scaling` prop; ERP screens are dense, so this matters. **Arabic**: the normaliser is not confirmed to feed Combobox, DataTable global search or FilterBar, it does not fold Arabic-Indic digits, and Hijri, bidi isolation for SKUs and phone numbers, and IQD formatting policy remain open. The notes also recommend isolating user-generated cells with `<bdi>` and forcing LTR on phone, email and URL inputs, which I could not confirm is done.

One gap sits outside every source: Kurdish (Sorani) uses extra Arabic-script letters and is spoken in the Kurdistan Region. If the Iraq market includes it, the normaliser, font coverage and locale files need checking. This is my background knowledge and is not in the notes.

## Confidence and gaps

Confidence is highest where primary sources were read (shadcn docs and GitHub listings, Base UI docs and release notes, Mantine/Chakra/Ark/React Aria index files, MUI docs, npm registry data) and lowest for commercial kits. The research notes were produced by a summarising fetch tool, and none of the packages were installed or tested, so every capability statement is "documented", not "verified working".

Counts conflict or are vendor-stated in several places. shadcn lists 66 component docs, the repo folder holds 61 components, and `r/index.json` returned 65 `registry:ui` items that look like a stale index, so the real block catalogue beyond 27 is unconfirmed. Tailwind Plus Application UI is 364 in one snapshot and 414 in another, both from third-party skill files, because the official pages are behind a login wall. The Shopify date is 9 September in one source and 14 September in another, with no primary statement found. MUI Scheduler is labelled beta in docs and alpha in the v9 blog; MUI's pricing page may predate the April 2026 application-based licence; Minimal's paid price is quoted from $69 and up to $599. PrimeReact is 94 components counted from v10 navigation versus "130+" in v11 marketing; Ant Design Charts is "27" versus "30+"; star counts for shadcn-admin range from 2.7k to 16.7k and for Kiranism from 5k to 7.3k across snapshots. Preline's 758 total is a sum of overlapping subcategories. Shadcnblocks (2,866 blocks), ReUI (1,265 components), Aceternity, Untitled UI (5,000+) and Kibo ("1,101 patterns") are marketing figures. Mantine UI and Mantine core both show 123 by coincidence.

Unreachable or unresearched: official Tailwind Plus counts, Flowbite Pro and Blocks (403), procomponents.ant.design and Fluent Storybook (SPAs), PrimeReact v11 component pages (404), Chakra Pro counts, PrimeBlocks pricing, Park UI's current activity (presets unpublished since 2024), RTL and Arabic status for Tailwind Plus, Untitled UI, Flowbite, daisyUI, Preline and Tremor, and licences for Kibo, coss, Dice UI, Magic UI and Cult UI. Not researched at all: PDF/print in RTL, phone input handling for Iraq, text truncation in mixed-direction cells, chart RTL behaviour, how Odoo/ERPNext handle Arabic, and what `Intl` actually returns for `ar-IQ` (digits, calendar, month names, IQD). The Iraqi preference for Latin versus Arabic-Indic digits has no authoritative source. My additions not in the notes are labelled as such: the Kurdish point, the effort estimates, and the print-documents item.

## What to do next

Start with a half-day spike that settles the calendar engine, because the Hijri decision gates both the calendar upgrade and the scheduler: run `Intl.DateTimeFormat` for `ar-IQ`, `ar-SA-u-ca-islamic-umalqura` and `ckb-IQ` across Node, Chrome and Safari, and test whether `@internationalized/date` can sit under the existing Date-based Calendar or whether an Intl-only grid is enough. Then, in order: finish `login-01` and publish the CLI plus a hosted registry (so blocks can be installed at all); build StatusBar, then the resource-list block, then the record-detail block, since those three create the first ERP demo that no free kit can match; ship the shared Arabic search and per-tenant locale provider alongside them because they are small; and schedule DataTable v2 as three independent deliverables (virtualisation and RTL keyboard, grouping and export, saved views). Defer scheduler, Gantt and print documents until a Playwright RTL pass is green and an Iraqi user has reviewed the numeral and month-name defaults.

## Conclusion

The research changes the framing: the competitive gap is not component count, where sas-ui's roughly 65 components already match antd's 73 and exceed Radix Themes' 56 and shadcn's 66 on ERP-relevant parts. It is the layer above, where shadcn publishes 27 blocks, Ant Design Pro is tied to Umi, and MUI's Toolpad has stopped adding features ([MUI 2026 and beyond](https://mui.com/blog/2026-and-beyond/)). A copy-in library avoids that coupling risk, and being Base UI-native, logical-CSS-only and Arabic-aware is a combination none of the checked kits currently offers. The Arabic features are cheap relative to their differentiation: Hijri, per-tenant numerals, shared search normalisation and bidi isolation are each days of work and none appears as a documented feature in any suite checked.

The main uncertainty is user-side, not technical. Whether Iraqi finance teams want Latin or Arabic-Indic digits, Gregorian or Hijri dates, and Levantine or Gulf month names is unanswered by every source, so the most valuable early artefact may be a one-page decision record validated with two or three real users before the settings defaults are frozen.
